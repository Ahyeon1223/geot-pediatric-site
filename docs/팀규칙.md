# 팀 규칙

처음 합류하면 이 파일부터 읽어 주세요. 바꾸고 싶은 규칙이 있으면 단톡방에서 얘기하고 고칩니다.

## 1. 절대 올리지 않는 것

| 무엇 | 이유 | 어떻게 막나 |
|---|---|---|
| API 인증키, `.env` 파일 | 공개 저장소라 누구나 볼 수 있음 | `.gitignore`에 들어 있음. 코드에 키를 직접 적지 않기 |
| `data/raw/`의 원본 데이터 | 용량이 크고 다시 받을 수 있음 | `.gitignore`에 들어 있음. 작은 샘플만 `data/sample/`에 |
| `.venv/`, `.idea/`, `__pycache__/` | 각자 컴퓨터마다 다름 | `.gitignore`에 들어 있음 |
| 개인정보 (전화번호, 학번 등) | 공개 저장소 | 올리기 전에 확인 |

**인증키는 단톡방에도 올리지 않습니다.** 각자 공공데이터포털에서 발급받아 자기 `.env`에 넣습니다.

## 2. 어디에 무엇을 두나

| 내용 | 위치 |
|---|---|
| 코드 | GitHub `src/`, `app.py` |
| 실행 결과, 검증표, 분석 결과 | GitHub `reports/` |
| 요구사항, AI 사용 기록, 팀 규칙 | GitHub `docs/` |
| 제출용 문서(PPT·워드), 회의 메모, 발표 자료 | 구글 드라이브 팀 폴더 |

같은 내용을 두 곳에 두지 않습니다. 드라이브 문서에서는 GitHub 파일을 링크로 가리킵니다.

## 3. GitHub 작업 순서

1. 작업 시작 전에 `git pull`
2. **내 역할 파일만** 고치기 (다른 사람 파일을 고쳐야 하면 단톡방에 먼저 말하기)
3. 작업이 끝나면 `git add` → `git commit -m "무엇을 했는지 한 줄"` → `git push`
4. push가 거절되면 `git pull` 하고 다시 push

| 역할 | 주로 고치는 파일 |
|---|---|
| 데이터 | `src/collect.py`, `src/clean.py`, `data/sample/`, `reports/count_check.md` |
| 서버 | `src/api.py`, `tests/` |
| 화면 | `app.py`, `README.md` |

## 4. AI 사용 기록

AI(Claude 등)에게 코드나 문서를 맡겼다면, 맡긴 사람이 `docs/prompts.md`에 한 줄 남깁니다. 날짜, 담당, 무엇을 요청했는지, 결과, **확인하고 고친 점**을 적습니다.
